# Shared Domain Model

## Core terms

| Term | Meaning |
|---|---|
| Workspace | One developer or agent working copy with a stable identity. |
| Repository member | A registered user permitted to access one repository's verified shared context. |
| Authorized agent | An agent acting within the repository permissions of a registered user. |
| Repository state | Repository identity, branch, base revision, current revision, and observation time. |
| Change manifest | Producer claim describing changed artifacts and linked evidence. |
| Evidence reference | A resolvable pointer to a repository fact or recorded command result. |
| Verification decision | Evidence-gate result for one manifest. |
| Admitted claim | Immutable verified projection allowed into shared context. |
| Claim lifecycle record | Mutable Shared Context state describing what happened after admission without rewriting the verified claim. Its exact states remain an open design question. |
| Active-work context | Verified description of work relevant to cross-workspace analysis. |
| Conflict finding | Evidence-backed statement that one verified change may affect another workspace. |
| Risk assessment | Explainable priority and confidence derived from findings and policy. |
| Alert | Targeted message containing the finding, evidence, recipient reason, and next step. |
| Alert outcome | Recorded acknowledgement, dismissal, coordination, test, or follow-up action. |
| Adaptation proposal | Human-reviewable plan or patch prepared in isolation. |
| Reconstructible observation | Temporary information that a later observation can reproduce safely and cheaply. |
| Durable handoff | Important or non-reconstructible information retained by its producer until a consumer durably and idempotently accepts it. |
| Alert threshold | Repository policy that determines when an evidence-backed risk requires an interruption or human supervision. |

## Stable identities

- `repository_id`: issued by the registration boundary for one logical repository, not a mutable filesystem path.
- `workspace_id`: issued by the registration boundary for one working copy.
- `producer_id`: issued by the identity or registration boundary for a manifest-producing component.
- `manifest_id`: generated by Workspace for one observation.
- `evidence_id`: generated by Workspace for one evidence reference.
- `decision_id`: generated by Verification for one verification decision.
- `claim_id`: generated by Verification for one admitted claim.
- `finding_id`: generated by Conflict Analysis for one analysis finding.
- `risk_assessment_id`: generated by Conflict Analysis for one risk assessment.
- `alert_id`: generated by Orchestration for one routed alert.
- `alert_outcome_id`: generated by Notification for one recorded alert outcome.
- `adaptation_request_id`: generated by Orchestration for one human-approved adaptation request.
- `proposal_id`: generated by Adaptation for one adaptation proposal.

The producing vertical also generates the idempotency key for retrying the same logical artifact. A transport may add a separate delivery identifier, but it must preserve the domain identifier and all upstream references.

## Verification states

- `verified`: all required gates passed; an admitted claim may be emitted.
- `rejected`: evidence contradicts the claim, policy forbids it, or a terminal contract rule fails.
- `needs_more_evidence`: the claim is plausible but required evidence is incomplete.

Only `verified` crosses the evidence gate.

## Verification levels

- `local`: checked against an identified author workspace.
- `shared_branch`: checked against an accessible shared branch revision.
- `mainline`: checked against an identified mainline revision.
- `attested_only`: reported without independently resolvable repository evidence.

`attested_only` provenance is recordable but is not sufficient for admission by default.
