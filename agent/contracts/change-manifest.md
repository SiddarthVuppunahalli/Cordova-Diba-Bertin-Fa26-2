# Change Manifest Contract

## Purpose

`ChangeManifest` is the versioned input to the Verification Agent. It is a claim from a producer, not verified truth.

## Version 1 draft shape

This is the shared boundary draft. Conditional field rules and serialized schemas must be approved before Version 1 is frozen.

| Field | Required | Meaning |
|---|---:|---|
| `contract_version` | yes | Exact contract version, initially `1`. |
| `manifest_id` | yes | Unique identifier generated by Workspace for this observation. |
| `idempotency_key` | yes | Stable key generated by Workspace and reused for retries of the same logical submission. |
| `repository_id` | yes | Logical repository identity issued by the registration boundary. |
| `workspace_id` | yes | Producer working-copy identity issued by the registration boundary. |
| `producer_id` | yes | Registered developer-agent, CLI, or collector identity. |
| `branch` | yes | Reported active branch. |
| `base_revision` | yes | Revision against which the change is described. |
| `current_revision` | conditional | Current commit when relevant; may be absent for a purely uncommitted state. |
| `observed_at` | yes | UTC observation timestamp. |
| `submitted_at` | yes | UTC submission timestamp. |
| `source` | yes | `manual`, `collector`, `hook`, or another registered source. |
| `publish_intent` | yes | Whether a developer explicitly requested that this candidate enter the verification workflow. |
| `changes` | yes | Non-empty list of reported path operations. |
| `evidence` | yes | Non-empty list of evidence references. |
| `visibility` | yes | Requested repository access scope, subject to policy. Version 1 supports `repository_members`. |
| `summary` | no | Concise untrusted producer summary. |

## Change entry

| Field | Required | Meaning |
|---|---:|---|
| `path` | yes | Repository-relative normalized path. |
| `operation` | yes | `add`, `modify`, `delete`, `rename`, or `copy`. |
| `previous_path` | conditional | Required for rename or copy. |
| `symbols` | no | Unverified structured symbol claims. |
| `evidence_ids` | yes | Evidence references supporting the entry. |

## Privacy constraints

- Paths, hashes, command metadata, and bounded structured facts are allowed.
- Raw diff bodies and full source files are excluded from Version 1.
- Summaries are untrusted and cannot substitute for evidence.
- Repository membership permits access to verified shared context but does not override the raw-source exclusion.
- Branch, component, and temporary-work attributes may guide relevance and lifecycle; they are not separate Version 1 authorization scopes.

## Implementation independence

Until the Workspace vertical exists, another vertical may construct manifests from local fixtures. The fixture builder must use the same shared contract type as a real producer and may not bypass consumer validation.
