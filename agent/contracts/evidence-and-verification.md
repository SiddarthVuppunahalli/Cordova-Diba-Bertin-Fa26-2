# Evidence and Verification Contracts

## EvidenceReference Version 1 draft

Evidence supplied by a producer is untrusted input. The Verification vertical computes the effective verification level; it does not accept the producer's level as fact.

| Field | Required | Meaning |
|---|---:|---|
| `evidence_id` | yes | Identifier generated by Workspace and unique within the manifest. |
| `kind` | yes | Registered evidence kind. |
| `repository_id` | yes | Repository to which the evidence belongs. |
| `revision` | conditional | Revision at which the reference is expected to resolve. |
| `locator` | yes | Structured resolver input; never an opaque prose claim. |
| `digest` | conditional | Integrity digest when evidence can change. |
| `observed_at` | yes | UTC time the evidence was observed. |
| `producer` | yes | Component that created the reference. |
| `claimed_verification_level` | yes | Producer claim: `local`, `shared_branch`, `mainline`, or `attested_only`; must be independently confirmed. |

## VerificationDecision Version 1 draft

| Field | Required | Meaning |
|---|---:|---|
| `contract_version` | yes | Decision contract version. |
| `decision_id` | yes | Unique identifier generated by Verification. |
| `manifest_id` | yes | Manifest being decided. |
| `status` | yes | `verified`, `rejected`, or `needs_more_evidence`. |
| `decided_at` | yes | UTC timestamp from the injected clock. |
| `checks` | yes | Ordered records of all executed checks. |
| `reason_codes` | yes | Stable machine-readable reasons. |
| `evidence_ids` | yes | Evidence used by the decision. |
| `explanation` | yes | Concise human-readable explanation grounded in checks. |
| `admitted_claim` | conditional | Present only when `status` is `verified`. |

## VerificationCheck

Each check contains:

- `rule_id`
- `rule_version`
- `outcome`: `pass`, `fail`, or `unknown`
- `reason_code`
- `input_refs`
- `evidence_ids`
- `started_at` and `finished_at`
- `details`, excluding unauthorized source

## AdmittedClaim Version 1

An admitted claim is a verified projection, not the original manifest. It contains only:

- A `claim_id` generated by Verification
- Stable repository, workspace, manifest, and decision identifiers
- Verified branch and revisions
- Verified path operations
- Allowed structured symbol facts, when available
- Evidence references and effective verification levels determined by Verification
- Observation and decision timestamps
- Approved `repository_members` visibility scope for the identified repository

The admitted claim is immutable and contains no mutable supersession, integration, convergence, withdrawal, or expiration status. Shared Context maintains that post-admission state separately. The exact lifecycle contract remains open.

## Initial reason-code families

- `contract.*`
- `workspace.*`
- `repository.*`
- `evidence.*`
- `observation.*`
- `submission.*`
- `visibility.*`
- `privacy.*`
- `dependency.*`

Reason codes are part of the public contract. Renaming one requires a contract-version decision.
