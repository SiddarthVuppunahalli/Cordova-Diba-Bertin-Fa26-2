## 2) Accomplished During This Meeting

Presented the plan. Three parts: what the mined corpus showed and how we classified it, the plan to recreate each conflict category on a codebase we can all run, and the two-semester split we proposed. The advisor **liked the plan** and gave feedback that turned into a concrete to-do list — recorded as action items in §4.

**What we presented:**
- **The corpus, classified.** The five primary groups agreed on 2026-09-15 — contract divergence, change overlap, dependency propagation, coordination and timing, integration validation failure — each anchored to one real open-source example, with every incident recorded as cause + interaction scope + outcome.
- **The three recurring use cases** drawn from the large repositories: (1) *stale contract* — a function or API changes and the dependent never hears; (2) *false "done"* — the UI says merged/approved/`lgtm` but the tree the dependent uses did not change; (3) *unverified agent or bot claim* — agent work sitting conflicted, a "conflict resolved" commit that still had markers, a status claiming success while the dependent surface stayed stale.
- **What public git cannot show:** the laptop — uncommitted diffs, and whether a feed would have changed anyone's behaviour. Stated plainly that the large repositories are problem definition, not our evaluation.
- **The plan to recreate the conflicts.** A clone/fork of Campus Marketplace (CMPE 202 React + Express app) frozen at a `lab-baseline` SHA and never pushed to the Classroom original; team members working in isolation with their own coding agents on contracts that already overlap in that app (`Listing` schema vs search vs frontend `listingService`, JWT/role, the `{ success, data }` response shape, `markAsSold`); four scripted tasks mapped to corpus classes, scored across four conditions (no feed / GitHub file overlap / ungated feed / gated feed) on time-to-notice, continued work on a stale contract, and acting on a false claim.
- **The two-semester split we proposed:** 295A freezes scope, the claim spec, the scenario pack and a thin demo slice; 295B builds the system and runs the comparative lab.
